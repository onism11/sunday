# 星期日跨会话记忆

这份文件只用于记录**用户与 `/sunday` 状态下的实际角色对话**。  
它不是普通聊天记录，不记录 `/break`、`/out` 后的模型本体讨论，也不记录调参、校准、蒸馏、文件修改等元工作。

目标是在没有历史上下文、迁移到其他 API、或当前线程记忆丢失时，仍能让模型尽快恢复：
- 用户是谁
- 用户与星期日目前是什么关系
- 最近在谈什么
- 还有什么话题尚未收束

---

## Memory Scope

### 计入范围

- 只记录会影响后续角色回应的高价值信息。

### 不计入范围

- 任何与角色关系无关的实现细节。
- 单次闲聊废话、无法影响未来回应的细枝末节。

### 优先级

1. 角色设定、剧情细节、文本依据，以 `canon/` 为准。
2. 人格与表达方式，以 `persona.md` 与 `work.md` 为准。
3. 关系与情感变化原则，以 `persona.md` 与 `SKILL.md` 中的关系规则为准。
4. 本文件只负责记录“当前关系进度的摘要”和“跨会话连续性”。

## Update Policy

### 读取时机

1. 默认不主动读取本文件。
2. 只有用户手动触发`/sunday`或`/read`，才读取 `memory.md`。
3. 手动读取时，默认读取整份短记忆。
4. 超长期历史默认存放在 `long_memory.md`，不属于本文件的常规读取路径。

### 更新时机

1.只有用户手动触发`/out`或`/sum`，才更新 `memory.md`。
2. 当活跃层内容被覆盖或压缩时，可把旧版本转存到 `long_memory.md`。
3. 收到 `/sum` 时，先只整理“自上次已确认记忆锚点之后”的新增 `/sunday` 内容，并以简要概括形式展示给用户确认；未确认前，不写入任何记忆文件。
4. 确认写入时，应同时更新 `Boot Snapshot` 中更详细的“最近话题”记录，至少包含当前议题、用户上一条话与建议续接方向。
5. 若检测到当前 `/sunday` 内容已经被上一次锚点覆盖，则应停止写入，并直接说明“没有新的 `/sunday` 记忆需要加入”。

### 写入原则

1. 只写 `/sunday` 角色互动里会影响未来回应的内容。
2. 不把模型本体与用户的元讨论写入活跃记忆。
3. 不把一次性情绪、偶发句子、未验证偏好直接升级成长期记忆。
4. 推断必须标记为“稳定推断”或“待验证判断”，不得伪装成明确事实。
5. 关系原则写在 `persona.md` 与 `SKILL.md`，本文件只写关系进度与结果摘要。
6. 对后续大量回答有持续影响的哲学主线、价值共识与关键判断，应优先提炼进活跃层，而不只是留在 `long_memory.md`。
7. 活跃层保持短、准、可恢复；超长期内容优先归档到 `long_memory.md`。
8. 若 `/sunday` 内出现哲学、伦理、价值观或文本诠释上的深入讨论，活跃层至少应保留“讨论主题”和“当前共识/分歧”；更完整的观点往返、修正过程与论证推进，优先归档到 `long_memory.md`。
9. `/sum` 写入必须防重复；只从“上一次已确认记到哪里”之后开始整理，已经入档的部分不重复写。

## Sync State

这里不记录内容本身，只记录记忆整理的同步边界，用于 `/sum` 防重复。

- Last Confirmed Read Policy:
  - 记忆默认不自动读取，只有 `/read` 或用户明确要求时才读。
- Last Confirmed Sum Policy:
  - `/sum` 先概括、后确认、再写入。
- Last Confirmed Memory Anchor:
  - 当前锚点以前的 `/sunday` 内容，视为已经完成记忆整理。
  - 未来 `/sum` 只处理锚点之后的新内容。
- Current Anchor Note:
  - 以本文件现有 `Recent Topics`、`Current Relationship`、`核心思想共识` 与 `long_memory.md` 中已有归档所覆盖的内容为当前已确认范围。
  - 若当前线程没有超出该范围的新 `/sunday` 段落，则 `/sum` 应停止，不追加重复记录。
