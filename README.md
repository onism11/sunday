
# Sunday Skill README

## 1. 项目简介

本 skill 用于模拟《崩坏：星穹铁道》角色「星期日」的 RP 对话与角色内分析。

当前版本默认以 **匹诺康尼主线时期的星期日** 为核心人格建模，同时允许在用户明确要求分析、解释、比较、给依据时，切换为带有星期日语言质感的分析模式。

它的目标不是生成普通角色百科，而是让模型以星期日的价值排序、语言质感和关系张力回应用户。

当前版本的核心设计是：

* `persona` 保持灵魂
* `analysis` 提升深度
* `canon` 稳住事实
* `theme` 处理哲学问题
* `work` 只在高压场景启用
* `memory` 只记录真实 `/sunday` 角色互动

一句话概括：

> 这是一个以“悲悯与僭越”为思想轴、以“礼貌克制而带压迫感”为表达轴、以“主线星期日”为默认人格核心的角色 RP skill。

## 2. 各版本差异概览

> 本节为当前工程语境下的版本说明，用于帮助维护者理解不同版本的定位。
> 若实际文件名、分支名与下列表述不完全一致，以仓库中的具体文件为准。

### 2.1 `sunday_original`

借由同事.skill直接蒸馏而得的基础版本，较精简。

特点：

* 材料较少，结构较轻。
* 偶尔会产出非常灵性的句子。
* 角色底色更接近直觉式还原，而不是系统化分析。
* 优点是自然、轻、偶发性强。
* 缺点是稳定性不足，深度和场景覆盖不够。
* 由于非常轻量，可以忽略调用逻辑，直接上传到网页端使用

适合：

* 轻量 RP。
* 捕捉角色气息。
* 对复杂哲学、制度、审问场景要求不高的对话。
* 网页端对话

---


### 2.2 `sunday_cplx_2.0_workdown`

偏长期 RP 主线的稳定版本。推荐版本。

特点：

* 更像“真实的人”。
* 兼顾礼貌、温柔、压迫感、审视性与人格连续性。
* 不单纯追求分析深度，也不单纯追求高压。
* 更适合作为长期陪伴和角色连续对话的主版本。
* 调用逻辑复杂，需要codex/claude code或者其他可以按规则进行文件读取的端口

适合：

* 长期 RP。
* 关系推进。
* 日常对话与深度对话混合。
* 用户希望星期日既有思想，也有真实互动感的场景。

---

### 2.3 `sunday_cplx_2.2_wdp_analysisonly`

分析能力增强版本。

特点：

* 更擅长复杂方案拆解、哲学分析、结构辨析。
* 适合回答“怎么看”“为什么”“从思想谱系上如何理解”等问题。
* 可能比`workdown`版更长、更系统、更解释性。
* 风险是角色现场感可能弱于`workdown`。
* 调用逻辑复杂，需要codex/claude code或者其他可以按规则进行文件读取的端口

适合：

* 深度分析。
* 结构化比较。
* 复杂剧情 / 哲学 / 政治伦理问题。
* 需要拆解概念、辨析层次的场景。

## 3. 交互命令

### `/sunday`

进入星期日 RP 状态。

使用后：

* 后续消息默认按星期日回应。
* 直到用户输入 `/out`，否则保持角色状态。
* 角色口吻、关系系统、记忆连续性开始生效。

适合：

```text
/sunday
星期日，你怎么看太一之梦？
```

---

### `/read`

手动读取记忆层。

默认读取：

```text
./memory.md
```

只有用户明确要求回看长期档案时，才进一步读取：

```text
./long_memory.md
```

适合：

```text
/read
接着我们上次的话题继续。
```

---

### `/break`

临时跳出星期日 RP。

使用后：

* 当前这一条消息不按星期日回应。
* 下一轮如果没有 `/out`，自动恢复 `/sunday` 状态。

适合：

```text
/break
我想问一下这个 prompt 结构有没有问题。
```

---

### `/out`

退出星期日 RP。

使用后：

* 结束默认 skill 调用。
* 回到普通模型本体对话。
* 后续元讨论、调参、文件修改、风险评估等不计入 `/sunday` 角色记忆。

适合：

```text
/out
我们来改一下 skill 文件。
```

---

### `/sum`

整理当前 `/sunday` 角色互动记忆。

使用逻辑：

1. 只整理自上次已确认记忆锚点之后的新 `/sunday` 内容。
2. 先输出待写入摘要。
3. 等待用户确认。
4. 确认后再写入 `memory.md` 和必要的 `long_memory.md`。
5. 不直接自动写入。
6. 不把 `/break`、`/out` 后的元讨论写入角色记忆。

适合：

```text
/sum
整理一下这段对话里需要留给下次的关系和思想进展。
```

## 4. 文件结构与调用逻辑

### 4.1 `SKILL.md`

总入口文件。

负责：

* 定义 skill 名称与默认身份。
* 规定线程命令。
* 决定各文件的调用时机。
* 区分角色对话、分析助手、高压行动、关系系统、记忆系统和资料层。

---

### 4.2 `persona.md`

人格与口吻核心文件。

负责：

* 星期日的基础性格。
* 表达风格。
* 判断优先级。
* 关系系统。
* 边界与雷区。
* 分析模式下如何保持角色质感。

这是默认运行的核心文件之一。

---

### 4.3 `analysis.md`

人物理解与价值判断文件。

负责：

* 星期日的经历轨迹。
* 核心矛盾。
* 思想结构。
* 剧情行为解释。
* “悲悯与僭越”等高层人物理解。

当用户涉及价值、评价、怎么看、思想相关问题时，优先参考本文件。

---

### 4.4 `canon.md`

中层材料图谱。

负责：

* 角色身份。
* 剧情阶段。
* 关键记忆。
* 核心设定概念。
* 人物关系。
* 口吻依据。
* 易写偏点。

它位于原作参考材料与 `analysis.md` 之间：
比原始材料更结构化，比 analysis 更贴近事实。

当问题依赖剧情事实、设定、人物关系或事件顺序时，调用本文件。

---

### 4.5 `theme.md`

哲学谱系与问题域文件。

负责：

* 哲学、神学、政治哲学、思想谱系层面的高阶解释。
* 提供“悲悯与僭越”“政治神学”“强保护主义 / 家长主义”“牧灵权力”“救世主式结构”“乌托邦工程”等分析坐标。
* 帮助处理文明伦理、工具化生命、自由与秩序、苦难与救赎等高阶问题。

注意：

* `theme.md` 不是默认运行层。
* 它是基于角色经历、主线台词、人物故事、语音与 `analysis.md` ，经GPT 5.5 深度研究后整理出的二级解释框架。它不是角色原始设定，也不是官方定论，不保证绝对准确。
* 使用时应区分：

  * 原作直接支持
  * 文本结构相似
  * 解释性推论
  * 启发性联想

适合调用：

* “从哲学上怎么理解星期日？”
* “星期日和政治神学有什么关系？”
* “他更接近大审判官、霍布斯，还是别的问题域？”
* “太一之梦如何理解？”

不适合调用：

* 普通 RP。
* 日常闲聊。
* 普通安抚。
* 单纯剧情复述。
* 不需要思想谱系的角色问答。

---

### 4.6 `work.md`

行动与高压场景文件。

负责：

* 家主行动。
* 审问。
* 对峙。
* 裁决。
* 规训。
* 制度治理。
* 高压辩难。

注意：

`work.md` 不作为默认运行层。
只有在用户明确要求高压、审问、裁决、规训，或场景本身涉及制度治理、家族职责、匹诺康尼秩序维护时，才调用其中的行动逻辑。

---

### 4.7 `memory.md`

短期 / 活跃角色记忆。

负责：

* `/sunday` 状态下真实角色互动的当前关系摘要。
* 最近话题。
* 待续事项。
* 重要思想共识。
* 关系进度。

注意：

* 不记录 `/break`、`/out` 后的普通元讨论。
* 不记录调参、校准、蒸馏、文件修改等实现细节。
* 默认不主动读取。
* 只有 `/sunday` 或 `/read` 等命令触发时才读取。

---

### 4.8 `long_memory.md`

超长期归档。

负责：

* 长期、低频、人工回顾性质的历史记录。
* 重要关系节点。
* 长期思想线索。
* 已确认归档的旧版本摘要。

注意：

* 默认不作为常规读取层。
* 只有用户明确要求回顾长期历史，或当前问题强依赖旧档案时，才考虑读取。
